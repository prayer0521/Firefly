# Harness 架构层级概览

![Harness思维导图](images/Harness思维导图.avif)

Harness 架构体系主要由四个核心层级构成，自下而上分别定义了 Agent 的能力边界、连接方式、构建逻辑及运行管控机制：

## 1. 能力层 (Skills / Tools)
- **核心定义**：Agent 的具体技能集合。
- **功能描述**：为 Agent 配备读写文件、操作 Excel、浏览器控制、数据库查询及摘要生成等具体工具（Tool），是 Agent 执行任务的物理基础。

## 2. 连接层 (API / MCP 等协议和接口)
- **核心定义**：Agent 与外部世界交互的通道。
- **功能描述**：通过 API 接口或 MCP（模型上下文协议）等标准“插头”，将能力层技能与外部服务（如天气服务）实际连通。若无此层，技能将无法触达外部资源。

## 3. 构建层 (Prompt 策略 / SDK / 框架 / 编排逻辑)
- **核心定义**：Agent 的组织与搭建方式。
- **功能描述**：
  - **系统 Prompt**：定义角色、风格、安全边界及输出格式的行为准则。
  - **Agent SDK**：提供对话循环、工具注册等基础封装组件。
  - **Agent 框架**：如 LangGraph、AutoGen，负责定义多 Agent 协作及工作流编排。
  - **任务编排**：处理子 Agent 调度、模型路由及复杂执行顺序。

## 4. 运行管控层 (执行环境 / 状态记忆 / 监控容错 / 评估优化)
- **核心定义**：Agent 稳定、长期、可控运转的保障体系。
- **功能描述**：
  - **执行环境**：利用 Docker 沙箱等隔离空间，确保操作安全。
  - **状态与记忆**：维护长期任务状态、会话日志及外置知识库，避免重复劳动。
  - **执行控制**：通过 Hooks/中间件实现重试、节流、监控及自动评估。
  - **可观测性**：结构化记录全链路轨迹，支持回放调试与持续优化。
