# 第一部分：我们先看一个真实项目

假设你在做：

## 抖音（TikTok）

用户刷视频。

看起来简单：

```text
用户打开APP
↓
看到视频
↓
点赞
↓
评论
↓
关注
```

但后面是一套巨大的系统。

---

# Top Down 看整个架构

```text
手机APP

    ↓

Nginx网关

    ↓

SpringBoot服务

    ↓

Redis缓存

    ↓

MySQL数据库

    ↓

Kafka消息队列

    ↓

推荐系统

    ↓

大数据平台
```

你现在只需要记住：

```text
前端
↓
接口
↓
后端
↓
数据库
```

实际上大厂是：

```text
前端
↓
网关
↓
业务服务
↓
缓存
↓
数据库
↓
异步系统
↓
数据分析
```

---

# 第二部分：一个请求到底怎么跑

假设：

用户点赞视频

---

## 第一步

前端点击按钮

```javascript
点赞
```

触发：

```javascript
axios.post(
    "/video/like",
    {
        videoId:1001
    }
)
```

这里不是json文件。

而是：

```text
HTTP请求
```

里面携带：

```json
{
  "videoId":1001
}
```

---

## 第二步

请求到服务器

例如：

```text
https://api.tiktok.com/video/like
```

先到：

Nginx

---

Nginx是什么？

很多新手以为：

```text
服务器
```

实际上：

```text
门卫
```

例如：

```text
用户1
用户2
用户3
```

都来了。

Nginx负责：

```text
排队
转发
负载均衡
```

---

# 为什么不用SpringBoot直接接？

因为：

```text
100万请求
```

直接打到SpringBoot：

```text
爆了
```

Nginx是专门用C语言写的。

极快。

---

# 第三步

进入SpringBoot

例如：

```java
@PostMapping("/video/like")
```

接收到：

```json
{
  "videoId":1001
}
```

---

SpringBoot干嘛？

业务逻辑。

例如：

```java
给视频点赞
```

---

它会调用：

```java
likeService.like()
```

---

# 第四部分：为什么需要数据库

点赞数必须保存。

否则：

```text
服务器重启
点赞没了
```

所以：

```java
insert into video_like
```

写入MySQL。

---

# MySQL本质是什么？

很多人误解。

觉得：

```text
数据库=存数据
```

其实：

数据库最厉害的是：

```text
索引
事务
查询优化
```

---

比如：

```sql
select * from user
where id=1001
```

为什么快？

因为：

```text
B+树
```

---

本质：

```text
算法
+
磁盘组织结构
```

不是因为函数多。

---

# 第五部分：为什么Redis比MySQL快

假设：

视频点赞数：

```text
1000000
```

---

如果每次点赞：

```text
MySQL
```

磁盘IO。

很慢。

---

Redis：

```text
内存
```

速度：

```text
纳秒级
```

MySQL：

```text
毫秒级
```

差1000倍以上。

---

所以：

点赞

直接：

```java
Redis +1
```

---

# Redis厉害在哪？

不是函数多。

本质：

```text
数据在内存
```

而不是磁盘。

---

同时：

Redis内部用了：

```text
HashTable
SkipList
QuickList
```

等高级数据结构。

---

# 第六部分：为什么还需要MySQL

如果只用Redis。

服务器断电：

```text
数据全没
```

---

所以：

```text
Redis
负责快

MySQL
负责可靠
```

这就是：

```text
缓存 + 数据库
```

经典架构。

---

# 第七部分：为什么需要Kafka

假设：

明星发视频。

100万人点赞。

---

每次点赞：

```text
更新数据库
发送通知
推荐系统更新
统计系统更新
```

---

如果同步执行：

```text
用户等5秒
```

体验极差。

---

所以：

```java
Kafka.send()
```

发一条消息：

```text
张三点赞了视频1001
```

---

然后：

```text
通知系统
推荐系统
统计系统
```

自己慢慢处理。

---

# Kafka本质是什么

很多人以为：

```text
消息队列
```

说了等于没说。

本质是：

```text
削峰填谷
```

---

比如：

双十一

突然：

```text
10万请求
```

---

数据库只能处理：

```text
1万请求
```

怎么办？

---

Kafka先存起来：

```text
10万条消息
```

后面慢慢消费。

---

# 第八部分：为什么需要微服务

最开始：

```text
一个SpringBoot
```

里面：

```text

后来：

```

---

这就是：

```text
微服务
```

```

```

你可能学Docker时：

```text
docker run

```

感觉很抽象。

---

实际上：

```text

```

---

生产环境：

```text
JDK21
MySQL5.7
Redis6
```

直接炸。

---

Docker作用：

```text
把环境打包
```

---

保证：

```text
我电脑能跑

```

# 第十部分：Kubernetes为什么出现

当你有：

```text
1000台服务器
```

的时候。

Docker已经不够。

---

因为：

```text
哪个容器挂了？

哪个机器爆了？

怎么扩容？
```

人工根本管不过来。

---

Kubernetes负责：

```text
自动部署

自动扩容

自动恢复
```

# 你接下来应该怎么学 GitHub 项目

不要一上来读代码。

先画图。

比如看到一个项目：

```text
SpringBoot
Redis
MySQL
Kafka
Vue
```

先问：

```text
用户是谁？

核心功能是什么？

请求从哪来？

数据存哪？

缓存在哪？

消息在哪？

部署在哪？
```

然后画：

```text
用户
 ↓
Vue
 ↓
Controller
 ↓
Service
 ↓
Redis
 ↓
MySQL
 ↓
Kafka
```

等这张图能画出来，你再看代码，就会知道：

```text
这个类为什么存在

这个中间件为什么存在

这个框架为什么存在
```

而不是陷入“这个API怎么调用”的细节里。

对于你这种情况，我更建议下一步直接拿一个完整的大厂级项目（例如外卖系统、短视频系统或电商系统），我带你按照**用户点击按钮开始，一路跟踪到数据库和服务器部署**，把每一个技术出现的原因和底层原理都串起来。这样你会第一次真正建立“后端全景地图”。
