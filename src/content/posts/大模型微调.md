# 大模型LoRA微调+API部署+前后端联调 

---

# 一、项目整体认知
## 1.1 项目学习目标
掌握**大模型轻量化工程落地全流程**：
无需本地高端显卡、无需昂贵算力，通过 LoRA 低成本微调，给通用大模型注入**专属行业/私有知识**，最终封装网络 API 接口，实现网页端 AI 实时对话交互，是新手入门大模型落地最友好的实战项目。

## 1.2 核心技术通俗精讲（核心）
核心作用：
- **SFT 有监督微调**：教模型「标准答案」。通过标注问答数据，让通用模型学会专属业务逻辑，是模型定制的基础。
- **RLHF 强化学习**：调模型「说话风格」。不更新知识，根据用户喜好优化回答语气（严谨/活泼/二次元）。
- **RAG 检索增强生成**：帮模型「实时查资料」。解决大模型知识滞后、无法获取最新动态数据的问题。
- **LoRA 低秩微调**：低成本微调方案。仅训练千分之一参数，显存、算力需求极低，个人云算力即可运行。
- **LLaMA-Factory**：国产零代码微调框架。可视化操作，屏蔽底层复杂代码，新手开箱即用。
- **FastAPI**：Python 高性能接口框架。将本地模型封装成网络接口，供前后端项目调用。
- **Transformer**：所有大模型的底层核心架构，是大模型学习的基础基石。

## 1.3 完整实操流程
*算力准备 → 云端远程开发环境搭建 → LLaMA-Factory 部署 → 国内镜像下载基座模型 → 自定义数据集 SFT 微调 → LoRA 权重合并 → FastAPI 接口部署 → 后端 Java 调用接口 → 前端页面交互测试*

# 二、核心技术原理（核心）
## 2.1 三大模型定制方案场景区分
### 2.1.1 SFT 有监督微调
**核心逻辑**：投喂固定「问题-标准答案」数据集，让模型固化专属知识与业务逻辑。
**适用场景**：固定不变的企业私有规则、行业专属知识、固定话术。
**实战案例**：让通用大模型学会「蟹堡王专属运营规则、汉堡制作流程」。

### 2.1.2 RLHF 强化学习
**核心逻辑**：不更新知识，仅优化输出风格。通过用户好坏反馈，让模型自主调整回答策略。
**两大主流算法**
- PPO：小步渐进优化，稳定性强，适合精细调优
- DPO：直接优劣对比，优化幅度大、速度更快，新手首选

### 2.1.3 RAG 检索增强生成
**核心逻辑**：模型不存储动态数据，用户提问时，实时检索外部知识库，结合最新数据生成答案。
**适用场景**：频繁更新的数据（菜单、活动、公告）、少量私有知识场景。

## 2.2 微调 vs RAG 选型对照表
| 方案 | 核心优势 | 核心短板 | 适用场景 |
|:--- |:--- |:--- |:--- |
| 模型微调 | 知识固化、无需检索、回答稳定、速度快 | 需要标注数据、训练耗时、无法实时更新 | 固定行业知识、长期不变的专属业务 |
| RAG 检索 | 零训练成本、支持实时更新、无需算力 | 需实时检索、依赖知识库质量、响应略慢 | 动态更新数据、少量私有知识 |

> **学习总结**：静态固定知识用微调，动态实时知识用 RAG；企业落地两者结合，个人入门优先掌握 LoRA 微调。

## 2.3 微调算法分类
### 2.3.1 全参数微调
训练模型**全部权重参数**，效果最优，但算力、显存要求极高。

### 2.3.2 LoRA 低秩微调（核心重点）
**通俗原理**：冻结原始大模型所有通用参数，仅新增两个极小低秩矩阵，专门学习用户的专属业务知识。
**核心优势**：训练参数减少 10000 倍，显存占用降低 3 倍，普通 GPU 即可运行，推理无延迟。
**关键知识点**：LoRA 仅产出增量参数，**无法单独使用**，训练完成必须与原模型合并权重，生成完整可部署模型。

## 2.4 微调框架选型
新手首选 **LLaMA-Factory**：国产开源、可视化零代码微调、完美适配国内网络、文档友好、报错少，是入门最优方案。

# 三、实操教程
## 3.1 环境准备


## 3.7 微调参数通俗配置
- 微调算法：LoRA（轻量化首选）
- 数据集：magic_conch（自定义数据集）
- 学习率：默认（过大不收敛、过小训练极慢）
- 训练轮数：3–10 轮（太少欠拟合、太多过拟合）
- 批处理大小：显存自适应，默认配置
- 验证集比例：0.1（10%数据用于评估模型效果）

训练后台运行（关闭终端不中断）：使用 `nohup` 命令启动训练。

## 3.8 模型评估与权重合并
### 效果判断
训练损失持续下降并趋于平稳 → 模型正常学习；
损失居高不下 → 检查数据集格式、学习率、轮数。

### 权重合并（必做步骤）
LoRA 增量参数无法独立部署，必须合并原模型权重：
```bash
mkdir -p /root/autodl-tmp/Models/deepseek-r1-1.5b-merged
```
在可视化页面选择上述路径，一键合并导出完整模型。

# 四、FastAPI 模型接口部署（核心工程能力）
## 4.1 创建部署专属环境
```bash
conda create -n fastApi python=3.10 -y
conda activate fastApi
conda install -c conda-forge fastapi uvicorn transformers pytorch
pip install safetensors sentencepiece protobuf
```

## 4.2 编写模型接口服务
核心逻辑：加载合并模型 → 接收文本参数 → 模型生成回答 → 返回 JSON 结果
```python
from fastapi import FastAPI
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

app = FastAPI()

# 替换为你的模型合并路径
model_path = "/root/autodl-tmp/Models/deepseek-r1-1.5b-merged"

# 加载分词器与模型
tokenizer = AutoTokenizer.from_pretrained(model_path)
device = "cuda" if torch.cuda.is_available() else "cpu"
model = AutoModelForCausalLM.from_pretrained(model_path).to(device)

# 对话生成接口
@app.get("/generate")
async def generate_text(prompt: str):
    inputs = tokenizer(prompt, return_tensors="pt").to(device)
    outputs = model.generate(inputs["input_ids"], max_length=150)
    generated_text = tokenizer.decode(outputs[0], skip_special_tokens=True)
    return {"generated_text": generated_text}
```

## 4.3 启动并测试接口
```bash
uvicorn main:app --reload --host 0.0.0.0
```
- `--reload`：开发热更新，修改代码自动重启
- `--host 0.0.0.0`：允许所有设备访问接口

**测试地址**：
```
http://localhost:8000/docs
```

# 五、前后端全链路联调
## 5.1 后端 Java 调用 AI 接口
核心逻辑：前端请求 → 后端中转 → 调用 FastAPI 大模型接口 → 返回结果

### 5.1.1 引入 HTTP 依赖
```xml
<dependency>  
    <groupId>org.apache.httpcomponents.client5</groupId>  
    <artifactId>httpclient5</artifactId>  
    <version>5.2.1</version>  
</dependency>
```

### 5.1.2 核心业务调用代码
```java
@Service  
public class ChatServiceImpl implements ChatService {  
    @Autowired  
    private RestTemplate restTemplate;  
    @Autowired  
    private AiServiceConfig aiServiceConfig;  

    @Override  
    public String callAiForOneReply(String prompt) {  
        String baseUrl = aiServiceConfig.getBaseUrl();  
        String url = String.format("%s/generate?prompt=%s", baseUrl, prompt);  
        GenerateResponse response = restTemplate.getForObject(url, GenerateResponse.class);  
        return response != null ? response.getGenerated_text() : "";  
    }  
}
```

### 后端启动

网页输入提问 → 前端传参后端 → 后端调用微调模型接口 → AI 生成专属回答 → 页面展示结果
